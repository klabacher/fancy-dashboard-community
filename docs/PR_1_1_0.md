# Pull request: Community packs for FancyDashboard 1.1.0

## Problem and resulting behavior

The Community repository contained nine packs with divergent package and manifest versions, incomplete permission declarations, one pack without its advertised entry point, empty settings surfaces, duplicated host libraries, stale legacy manifests, and a Calendar/To-Do integration that could invoke storage under the wrong plugin identity.

This change prepares all nine packs for the Core 1.1.0 portable-pack contract, hardens release verification, and fixes the cross-pack task architecture. The final public permission declarations remain deliberately uncommitted until explicit security approval.

## Architecture and major changes

- Consumes the canonical Core SDK and Runtime from the composed Integration workspace.
- Builds portable fancy-browser-v1 artifacts with host singletons externalized.
- Verifies ESM, CommonJS, declarations, runtime exports, manifests, versions, widgets, and permission coverage.
- Regenerates the composed lock without the obsolete ArcGIS and deck.gl dependency tree.
- Removes five conflicting legacy JSON manifests and rejects any recurrence.
- Removes the unnecessary private Core token from the public checkout workflow.

## Pack inventory

### Calendar

Replaces the bundled To-Do bridge client with a narrow validated snapshot, request, and command event adapter. Calendar no longer owns To-Do storage identity or permissions. Four tests and a compiled artifact scan prove cross-bundle behavior without embedded To-Do commands or imports.

### Clock

Aligns 1.1.0 metadata and the portable build. Its reviewed permission proposal discloses Open-Meteo access.

### Launcher

Aligns 1.1.0 metadata, portable exports, and bridge usage. The reviewed permission proposal covers user-selected shortcuts, shell execution, and public HTTP/HTTPS favicon retrieval. Core blocks private, loopback, credential-bearing, and non-HTTP(S) favicon targets.

### LoL Player Stats

Aligns metadata and portable output. Core now enforces exact store read/write and Riot network floors for its five native commands; the Community manifest still awaits the reviewed declaration update.

### PC Monitor

Aligns metadata, exports, and nullable settings. Its reviewed proposal discloses system specs, telemetry, and widget storage.

### Productivity Suite

Aligns metadata and portable output. It requires no native permission declaration.

### To-Do

Adds serialized snapshot persistence, validated cross-bundle payloads, defensive copies, recovery, and cleanup. Six tests cover ordering, malformed events, commands, requests, subscription cleanup, and persistence recovery.

### Weather

Removes development-only release code and a dead alternate widget, fixes CommonJS output, and makes visual particles deterministic. Its reviewed proposal discloses Open-Meteo access.

### MapCN

Adds the missing public entry point so advertised ESM, CommonJS, declarations, and portable artifacts are produced. Its reviewed proposal discloses network capture and widget storage.

## UI and UX

Empty global settings panels were removed in favor of Core's explicit nullable contract. Weather visuals are stable across renders. Metadata, summaries, tags, repository links, minimum Core compatibility, and pack versions are aligned for Marketplace presentation.

## Security and permissions

The built-pack verifier compares compiled runtime capabilities, source bridge manifests, and public catalog declarations. It maps tauri:fs to fs:scope and tauri:shell to shell:exec and reports every omission.

The reviewed matrix is documented in PERMISSIONS_1_1_0.md. Scope arrays are user-visible metadata; the current Core bridge enforces permission kind rather than path or origin allowlists. Because Launcher needs broad user-selected filesystem, shell, and public web access, persisting this matrix requires explicit approval.

## Validation

- Source verifier passes for exactly nine packs.
- SDK, Runtime, and all nine Community packs build in the composed workspace.
- Calendar and To-Do: 10 tests pass.
- Calendar artifact scan contains no To-Do bridge command, identity, or package import.
- Two pre-permission portable artifact generations are byte-identical.
- Every ZIP contains exactly index.js and manifest.json.
- Production dependency audit reports no known vulnerabilities at the configured threshold.
- Formatting and diff checks pass.
- Built permission coverage intentionally fails with the documented omissions until approval.

## Breaking changes and migration

Core 1.1.0 is now the minimum supported host. Package and manifest versions must agree. Empty global settings exports are removed. Calendar no longer imports the To-Do package directly; cross-pack task behavior uses the event protocol.

## Risks and remaining gates

- Explicit approval is required before persisting the seven sensitive public permission updates and Launcher runtime permissions.
- All nine packs must be rebuilt and reproduced twice after that change.
- Native install, activation, update, removal, failure recovery, persistence, and Calendar/To-Do interaction remain blocked by unavailable Computer Use.
- This PR depends on the Core 1.1.0 contract. The Integration PR must pin the final Core and Community SHAs.
